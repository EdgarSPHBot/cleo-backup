## OpenClaw model visibility fix (with David)

**Problem:** After David upgraded me to OpenClaw 2026.9.6, newer Anthropic models
(Sonnet 5 / Opus 5) were not visible. `openclaw models refresh` reported
"unchanged (44 providers, 1038 models)" but nothing new ever appeared, and
`openclaw setup` reported "no models available".

**Wrong turns I took first (don't repeat these):**
- Blamed auth profiles / `Auth: no` column in `models list`. Not the cause.
- Had David re-run `models auth paste-api-key` twice. Unnecessary.
- Blamed the bundled `@anthropic-ai/sdk` being 0.125.0 vs 0.129.0 on npm. Not the cause.
- Chased `openclaw setup` behavior, which is the onboarding wizard, not a model manager.

**Actual root cause:** config had `models.mode: "replace"`.
Per the config schema: `"merge"` keeps built-ins and overlays custom providers,
`"replace"` uses ONLY the configured providers. So OpenClaw was discarding its
entire built-in catalog and using only the ~15 hand-written models in config.
Refreshing the catalog did nothing because the refreshed catalog was then thrown away.

**Fix:** routed a targeted single-field change through the `openclaw` tool:
`models.mode` `"replace"` -> `"merge"`. `reloadKind: hot`, no gateway restart.

**Verified after:**
- `models.mode` = `merge`
- `models.providers.anthropic` intact: baseUrl, auth, apiKey, all 5 original models preserved
- Model count 15 -> 27
- `anthropic/claude-sonnet-5` now present (alias: `sonnet`)
- `anthropic/claude-opus-5` now present (alias: `opus`, and now the default)

**Lesson:** when models refresh reports success but nothing changes, check
`models.mode` BEFORE touching auth, keys, or SDK versions.

**Still open / minor:** `openclaw setup --json` hangs without a TTY (times out at 25s).
Earlier in the session it did return JSON showing `apiKeys.anthropic: false`.
Not blocking anything — setup is the onboarding wizard, not needed on a live gateway.
